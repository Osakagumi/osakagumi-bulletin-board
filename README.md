# 大坂組社内ポータルサイト セットアップ手順

対象：お知らせ・行き先（社員の所在管理）・会議室や車輌の時間枠予約・測量機器やドローンの貸出管理・年間カレンダー・安否確認など、社内の各種業務をまとめた社内ポータルサイト（スマホ・PC対応）

構成：Firebase（Auth + Firestore）+ 静的HTML（GitHub Pages等でホスト可）。メール送信にEmailJS、カレンダーのExcel出力にExcelJS（`calendar_template_master.xlsx`という雛形ファイルを使用）、お知らせ添付ファイルの保存にGoogle Apps Script経由のGoogleドライブ連携を利用しています。

---

## 1. Firebaseプロジェクトを作成する

1. https://console.firebase.google.com/ にアクセスし、Googleアカウントでログイン
2. 「プロジェクトを追加」→ プロジェクト名を入力（例：osakagumi-booking）→ 作成
3. 左メニュー「構築」→「Authentication」→「始める」
   - 「Sign-in method」タブで「メール/パスワード」を有効化
4. 左メニュー「Database と Storage」→ サブメニュー「NoSQL」内の「Firestore」→「データベースの作成」
   - ロケーションは asia-northeast1（東京）推奨
   - セキュリティルールの開始モードはどちらを選んでもOK（手順3で上書きします）
   - ※Firebaseコンソールは改修が入ることがあるため、メニュー名が変わっている場合は「Firestore」で検索すれば見つかります
5. 左メニュー「プロジェクトの設定」（歯車アイコン）→「全般」タブ→ 下にスクロールし「アプリを追加」→ ウェブアプリ（`</>`アイコン）を選択
   - アプリ名を入力（例：booking-web）→ アプリを登録
   - 表示される `firebaseConfig` の値（apiKey, authDomain, projectId など）をコピー

## 2. 設定ファイルを編集する

`firebase-config.js` を開き、`firebaseConfig` の中身を手順1でコピーした値に書き換えてください。

必要であれば `BUSINESS_HOURS`（予約可能時間帯・時間単位）もここで調整できます。設備のカテゴリ（会議室・業務共用車輌・測量機器・ドローンなど）は、`firebase-config.js`内の`CATEGORIES`が初回アクセス時の初期データとして使われたあとはFirestoreで管理される方式になっており、admin.htmlの「設備管理」タブから追加・編集・削除できます。

## 3. Firestoreのセキュリティルールを設定する

1. Firebaseコンソール →「Firestore Database」→「ルール」タブ
2. `firestore.rules` の中身を全てコピーして貼り付け →「公開」

## 4. 最初の管理者を登録する

1. Firebaseコンソール →「Authentication」→「Users」タブ →「ユーザーを追加」
   - 自分（ヒネさん）のメールアドレスとパスワードを設定
2. Firebaseコンソール →「Firestore Database」→「データ」タブ
   - 「コレクションを開始」→ コレクションID：`admins`
   - ドキュメントID：先ほど登録したメールアドレスをそのまま入力（例：`hine@osakagumi.co.jp`）
   - フィールドは何も入れなくてOK（保存を押せばドキュメントだけ作成されればよい）

これで、そのメールアドレスでログインすると管理画面（admin.html）が使えるようになります。

## 5. 利用者アカウントを追加する

利用者が増えるたびに、Firebaseコンソール →「Authentication」→「Users」→「ユーザーを追加」でメールアドレスとパスワードを発行してください（社内の共有アカウント運用ではなく、個人ごとの発行を推奨します＝誰が予約したか分かるようにするため）。

管理者にしたい人だけ、手順4と同様に `admins` コレクションにメールアドレスのドキュメントを追加してください。

## 6. 設備を登録する

1. ログイン後、右上「管理画面」リンクから admin.html を開く
2. 「設備管理」タブで、測量機器・会議室・業務共用車輌をそれぞれ追加

## 7. 公開する（GitHub Pagesの例）

タイムカードPWAと同様の手順で問題ありません。

```
git init
git add index.html admin.html firebase-config.js firestore.rules
git commit -m "大坂組社内ポータルサイト 初版"
git remote add origin <あなたのリポジトリURL>
git push -u origin main
```

GitHub リポジトリの Settings → Pages で公開すれば、
`https://<ユーザー名>.github.io/<リポジトリ名>/index.html`
からスマホ・PCどちらでもアクセスできます。

## 追加機能：お知らせ／行き先ボード／安否確認

Firestoreのルールを更新したので、以前のバージョンから引き継ぐ場合は必ず`firestore.rules`を貼り直してください（手順3と同じ操作）。

### ユーザー登録（CSV一括）

admin.htmlの「ユーザー登録」タブから、複数人のアカウントをまとめて作成できます。

**CSVの形式**（1行目はヘッダーとして無視されます）

```
社員番号,氏名,所属,管理者フラグ,お知らせ投稿フラグ,メールアドレス,パスワード,電話番号,備考
1001,山田太郎,工務部,,1,yamada@osakagumi.co.jp,Osaka2026!,090-1234-5678,現場責任者
1002,佐藤花子,総務経理部,1,1,sato@osakagumi.co.jp,Osaka2026!,090-2345-6789,
```

- 必須は「メールアドレス」「パスワード」のみで、他の列は空欄でも構いません
- 管理者フラグ・お知らせ投稿フラグは `1` / `TRUE` / `○` / `はい` のいずれかで有効になります（空欄は無効）
- 所属欄は「行き先管理」タブで事前に登録した部署名と完全一致させてください（一致しない場合は未所属で登録されます）
- パスワードは全員同じ簡易なもの（例：`Osaka2026!`）でも構いません。本人が変更したい場合は、ログイン画面から「パスワードを忘れた方はこちら」のような機能は現状ないため、管理者がFirebaseコンソールの「Authentication」→「Users」から個別にパスワードをリセットしてください
- ファイル選択後「内容を確認する」で登録前のプレビューが出るので、内容を確認してから「この内容で登録を実行する」を押してください
- 既にアカウントが存在するメールアドレスは自動的にスキップされます（エラーにはなりません）
- 社員番号・電話番号・備考は、後から「行き先管理」タブの社員一覧でも編集できます

### お知らせ
- 管理者は常に投稿できます。管理者以外にも投稿を許可したい場合は、admin.html「お知らせ管理」タブでメールアドレスを追加してください。
- 投稿の閲覧は全員可能です。

### 行き先ボード
- ログインすると、その人の行が自動的に「社員名簿」に追加されます（氏名はメールアドレスの@より前が仮の名前として入ります）。
- admin.html「行き先管理」タブで以下を設定してください（初回のみ）。
  1. 「所属（部署）」を必要な数だけ登録（例：役員、総務経理部、営業部、工務部）
  2. 「行き先ステータス」で「初期セット（在席・外出・現場・休み）を作成」ボタンを押す（後から自由に追加・編集・削除できます）
  3. 「社員一覧」で各社員の正しい氏名・所属・並び順を編集
- 通常、自分の行き先は自分だけが変更できます。受付のように他の人の行き先も変更できるようにしたい場合は、同タブの「他者の行き先を設定できる人」にメールアドレスを追加してください。

### 安否確認
- admin.html「安否確認管理」タブから発信します。発信すると、それまでの安否確認は自動的に終了扱いになります。
- 社員側（index.html）は「安否確認」タブに表示される内容に、無事です／被害があります／わからない・確認中＋コメントで回答します。
- 管理者側は同タブで、社員名簿と回答を突き合わせた一覧（未回答者はオレンジ色で表示）を確認できます。過去の安否確認もプルダウンから選んで見返せます。

## 追加機能：年間休日カレンダー

「カレンダー」タブで、年度（4月始まり）単位の休日カレンダーを表示・編集できます。

- レイアウトは4月・10月、5月・11月…と2列×6行で並ぶ、会社の年間カレンダー資料と同じ形式です
- 「◀」「▶」で年度を切り替えられます
- **カレンダー編集権限者・管理者**は、日付をクリックすると休日のON/OFFを切り替えられます。備考（月ごとの休日名など）の文字部分をクリックすると、名称を入力・編集できます
- 権限がない人は閲覧のみです

### カレンダー編集権限の登録

admin.htmlの「カレンダー管理」タブから、メールアドレスを登録してください。管理者は常に編集できます。

### 初期データ作成（年度指定・最大3年度まで保存）

admin.htmlの「カレンダー管理」タブから、**任意の年度**を指定して初期データを一括作成できます。以下のルールで自動作成されます。

- 土日：休日
- 国民の祝日：休日（インターネット上の祝日API「holidays-jp」から祝日名を自動取得・入力。取得できなかった年度は休日のみ設定され、祝日名は手動入力が必要です。祝日APIは実務上、前年・当年・翌年あたりのデータしか持っていないことが多く、遠い将来の年度は祝日名が取得できない場合があります）
- 各月の第1土曜日：出勤（備考「地下道清掃」）

カレンダーは**最大3年度分**まで保存できます。4年度目を作成しようとすると、「カレンダーは最大3年度分まで保存できます。どの年度を削除しますか？」と表示され、既存の3年度から削除する年度を選べます（削除後、もう一度「作成する」を押してください）。「保存されている年度」の一覧からも、いつでも個別に削除できます。

作成後は、「カレンダー」タブから日付ごとに自由に調整してください（夏季休暇・冬季休暇・創業記念日など、会社独自の休みは含まれていないため、必要に応じて手動で追加してください）。

### Excel出力

**一般画面（index.html）の「カレンダー」タブ**に「Excel出力」ボタンがあります。押すと、現在表示している年度のカレンダーをExcelファイルとして書き出せます（以前はadmin.htmlにありましたが、一般画面に移動しました）。

**この機能を使うには、`calendar_template_master.xlsx` というファイルを、`index.html`・`admin.html`と同じ場所（リポジトリ直下）に置いてください。** これは、最初にアップロードいただいたサンプル資料をもとに、罫線・文字色・フォント・列幅・行の高さなどをすべてそのまま流用しつつ、どの月でも最大6週分の日付が入るように枠を整えた「雛形」ファイルです（Claudeが作成済みのものをお渡ししています）。「Excel出力」を押すたびに、この雛形をブラウザ上で読み込み、日付・祝日名・休日の色分けだけを差し替えて書き出します。

- 労働日数・休日数は各月の見出し部分に自動計算した実際の値で書き込まれます（雛形にあった数式は、年度によって参照がずれるため使っていません）
- 罫線・フォント・列幅・行の高さ・欄外の注記（創業記念日や労働時間に関する説明文など）は、雛形のものがそのまま残ります。ただし欄外の注記は2026年度向けの内容のままなので、他の年度で使う場合は必要に応じて手動で書き換えてください
- 雛形ファイルが見つからない場合はエラーになります。リポジトリへの配置をご確認ください

## 追加機能：定時・行き先の事前設定・時間休

### 定時（就業時間）の設定

admin.htmlの「行き先管理」タブに「定時（就業時間）の設定」パネルがあります（初期値：始業8:00、終業17:00）。この定時をもとに、行き先の表示ルール・時間休の範囲が計算されます。

### 行き先の表示ルール（一般画面・サイネージ共通）

- **定時の15分前〜15分後の間だけ**、通常の行き先表示になります。それ以外の時間は、全員「時間外」と表示されます
- 定時内での表示の優先順位は次の通りです
  1. 本人がその日「自分の行き先を入力」でその場で変更していれば、その内容
  2. その日の分として「事前設定」されている内容
  3. 「初期状態」として保存されている内容
  4. どれもなければ「未設定」
- 時間休（AM休・PM休・時間休）は、上記より優先して「休み」表示になります

### 事前設定・初期状態（行き先設定権限者・管理者向け）

「行き先」タブに「事前設定」というボタンが追加されます（行き先設定権限者・管理者にのみ表示されます）。

- 好きな日付を指定して、全員分の行き先をまとめて事前設定できます（一般画面の一覧と同じ見た目です）
- **休日には設定できません**（カレンダーで休日になっている日は選択できません）
- 事前設定は**最大7日分**まで保持されます。8日目を追加しようとすると、最も古い日付を削除してよいか確認が出ます
- **過去の日付の事前設定は自動的に削除されます**
- 「この内容を初期状態として保存」を押すと、事前設定されていない日を開いたときの初期値（フォールバック）として使われます

### 時間休（全員が利用可能）

「行き先を入力」画面から、「時間休」「AM休」「PM休」を設定できます。

- **AM休**：定時開始の15分前 〜 13:00
- **PM休**：12:00 〜 定時終了の15分後
- **時間休**（個別指定）：定時の範囲内（初期値8:00〜17:00）で、30分単位で開始・終了時刻を指定
- 設定すると、備考欄に「AM休」「PM休」または「時間休 10:00〜11:30」のように表示されます（この表示は1日中残ります）
- 該当する時間帯の間だけ、状態が自動的に「休み」表示に切り替わります（「休み」という名前のステータスが行き先ステータスに登録されている必要があります）
- 時間が経過すれば、自動的に元の状態表示に戻ります（画面は1分ごとに再描画されるので、時間になれば自動で切り替わります）

## 追加機能：行き先ビューの表示設定・サイネージ表示

### 表示設定（列数・幅・文字サイズ）

admin.htmlの「行き先管理」タブに、**一般画面用**と**サイネージ表示用**、それぞれ独立した設定パネルがあります（片方を変更してももう片方には影響しません）。

- **列数（1〜4）**：PCなど画面が広い場合の列数。スマホなど狭い画面では常に1列になります。
- **表示エリアの最大幅**：一覧全体の最大幅（px）。空欄なら無制限（画面いっぱい）です。
- **文字サイズ**：離れた場所から見るサイネージ表示は大きめ、情報量を増やしたい一般画面は標準〜小さめ、といった使い分けができます。

### サイネージ表示（玄関などの大型ディスプレイ用）

`index.html?display=1` というURLで開くと、ヘッダーや他のタブを隠し、「行き先」だけを画面いっぱいに自動縮小して表示する専用モードになります。admin.htmlの「行き先管理」タブから「サイネージ表示を開く」リンクでも開けます。

- 人数や項目数が増減しても、画面に収まるよう自動的に縮小・拡大されます
- 列数・幅・文字サイズ・初期表示（一覧／ボード）は、同タブの「サイネージ表示」パネルから設定できます（一般画面とは別設定です）
- ログインは通常のログイン画面から一度行うだけでOKです。以降はブラウザを開きっぱなしにしておけば、リアルタイムで自動更新されます
- 動作確認済みの想定端末：PC＋外付けモニター。将来的にタッチパネル端末に置き換えても、行き先の状態変更ボタンはそのまま操作できます

**運用上の注意**：ブラウザのキャッシュクリアやログアウト操作をすると再ログインが必要になります。専用端末として使う場合は、誤って他の操作をしないよう気をつけてください。

## 追加機能：お知らせのファイル添付（Google Apps Script 経由のGoogleドライブ連携）

添付ファイルの保存には、`osakagumi.sys@gmail.com`名義で公開する**Google Apps Scriptの「Webアプリ」**を経由して、Googleドライブに保存する方式を使っています。Webアプリは「実行するユーザー：自分（osakagumi.sys@gmail.com）」として動くため、**呼び出す社員側は一切ログインする必要がありません**。クレジットカードの登録も不要です（Apps Scriptは無料）。

### 投稿から1ヶ月経過後の自動削除

投稿から1ヶ月経過したお知らせは、誰かがログインした時・誰かが新しいお知らせを投稿したタイミングで自動的に完全削除されます。管理者がログイン／投稿した場合は全員分、一般の投稿権限者がログイン／投稿した場合は自分が投稿したお知らせの分だけが対象になります（削除できる範囲がそれぞれの権限に一致するようにしています）。

添付ファイルがあった場合も、その場でApps Script経由でドライブ上のファイルをゴミ箱に移動します（Googleドライブの仕様で、ゴミ箱に入ったファイルは30日後に自動で完全削除されます）。ログインを求められることはありません。

お知らせ投稿モーダルに「ファイル添付」ボタンがあります。押すとドラッグ＆ドロップ用の画面が開き、ファイルをドロップすると自動的にアップロードし、共有リンクを「リンク」欄に自動で入力します。

### 初期設定（1回だけ、`osakagumi.sys@gmail.com`でログインして行ってください）

1. https://script.google.com を開き、「新しいプロジェクト」を作成
2. 本リポジトリの`apps-script-storage.gs`の中身を丸ごと貼り付ける
3. コード冒頭の`SECRET`を、長いランダムな文字列（20文字以上推奨）に書き換える
4. Googleドライブに添付ファイル保存用のフォルダ（例：「お知らせ添付」）を作成し、フォルダを開いたときのURL（`.../folders/フォルダID`の部分）からフォルダIDを取得して、コード冒頭の`FOLDER_ID`に貼り付ける
5. 画面右上「デプロイ」→「新しいデプロイ」→ 種類の選択で「ウェブアプリ」を選択
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**
   - 「デプロイ」をクリックし、発行された「ウェブアプリのURL」を控える
6. 控えたURLと、手順3で決めた`SECRET`を、`firebase-config.js`の`GAS_STORAGE_CONFIG.webAppUrl` / `GAS_STORAGE_CONFIG.secret`に貼り付ける
7. `storage-helper.js`というファイルが新しく増えています。`index.html`・`admin.html`と同じ場所（リポジトリ直下）に置いてください

以上で完了です。GoogleドライブのOAuth設定（クライアントID・OAuth同意画面など）や、Firebase Storageの有効化・Blazeプランへの切り替えは一切不要です。

**コードを後から書き換えた場合**：Apps Scriptの「デプロイを管理」画面で「新バージョン」を選んで再デプロイしないと、変更が反映されない点にご注意ください。

### 運用時の注意

- アップロード・削除の際、ログインは一切求められません（Apps Scriptが`osakagumi.sys@gmail.com`として自動的に処理します）
- アップロードされたファイルは自動的に「リンクを知っている全員が閲覧可」になります（社外の人にも共有リンクとして送れます）
- 「ドラッグ＆ドロップ」はドロップした瞬間に自動アップロードされますが、「クリックしてファイルを選択」の場合はブラウザの仕様上、選択後に「アップロードする」ボタンをもう一度押す必要があります
- お知らせを削除すると、添付されているドライブ上のファイルもゴミ箱に移動されます（30日後に自動で完全削除）
- 添付付きのお知らせを編集し、別のファイルに差し替えた場合（またはリンクを削除した場合）も、以前添付されていたファイルは同様にゴミ箱に移動されます
- ファイル容量は`osakagumi.sys@gmail.com`のGoogleドライブ容量に依存します。無料の個人アカウントであれば通常15GB（Gmail等と共有）です
- Apps Scriptには実行時間の上限（1回の処理につき6分程度）がありますが、お知らせ添付程度のファイルサイズであれば問題になりません

## 追加機能：測量機器・ドローンの貸出管理

「予約」タブの中で、測量機器・ドローンだけは時間枠を予約する方式ではなく、**在庫中・貸出中・点検中・故障中**を切り替える貸出管理方式になっています（カテゴリを選ぶと自動的に切り替わります）。

### 状態遷移のルール

| 現在の状態 | 変更先 | 誰が操作できるか |
|---|---|---|
| 在庫中 | 貸出中 | 誰でも |
| 在庫中 | 点検中 | 誰でも |
| 貸出中 | 在庫中 | 測量機器管理者 または 借りている本人 |
| 貸出中 | 点検中 | 測量機器管理者 または 借りている本人 |
| 点検中 | 在庫中 | 測量機器管理者 または 借りている本人 |
| 点検中 | 貸出中 | 測量機器管理者 または 借りている本人 |
| （在庫中以外）→ | 故障中 | 測量機器管理者 または 借りている本人 |
| 故障中 → | 他の状態 | 測量機器管理者 または（故障前から）借りている本人 |

「貸出する」を押すと、任意で「返却予定日」を入力できます。誰がいつから借りているかは、カードに常に表示されます。

### 測量機器管理者の登録

admin.htmlの「設備管理」タブ下部「測量機器管理者」から、メールアドレスを登録してください。管理者は常にこれらの操作が可能です。この権限を持つ人は、各機器の「前回点検日」も編集できます。

### 既知の制約

- 状態変更の権限チェックはFirestoreのセキュリティルールと画面表示の両方で行っていますが、この規模の社内ツールとして「性善説」寄りの簡易な設計にしています（例：在庫中の設備は、誰でもどのフィールドでも書き換えられる状態になっています）。厳密な権限分離が必要な場合はご相談ください。

## 補足・既知の制約

- **同時予約の競合**：ほぼ同時刻に同じ枠を2人が予約しようとした場合、ごく稀に両方登録されてしまう可能性があります（サーバー側トランザクション未実装のため）。予約が重複した場合は管理画面の「予約状況」タブから片方を取消してください。頻発するようであれば、Cloud Functionsによる排他制御の追加をご相談ください。
- **管理者判定**：`admins` コレクションのドキュメントIDにメールアドレスをそのまま使う簡易方式です。社内利用の範囲では十分ですが、より厳密にするならCustom Claims（Cloud Functions要）への切り替えも可能です。
- **予約時間帯**：デフォルトは6:00〜20:00・30分単位です。`firebase-config.js` の `BUSINESS_HOURS` で変更できます。
- **安否確認の通知**：EmailJS（無料枠：月200通）を使って、発信時に社員名簿の全員へメール通知できます。設定方法は下記「メール通知（EmailJS）の設定」を参照してください。未設定のままでも動作し、その場合はシステム内表示のみになります。

## 各種上限・制限事項まとめ

制限には大きく2種類あります。①アプリ自身がコード上で明示的にチェックしている上限と、②裏側で使っている外部サービス（Firebase・EmailJS）自体の無料枠による上限です。

### ① アプリが自分で設けている上限

| 機能 | 上限 | 超えたときの挙動 |
|---|---|---|
| カレンダー | 最大3年度分 | 4年度目を作ろうとすると、どの年度を削除するか選ばせる確認画面が出ます |
| 安否確認（発信履歴） | 最大5セット | 6セット目を発信すると、一番古いものを自動削除します（回答データも含めて） |
| 行き先の事前設定 | 最大7日分 | 8日目を追加しようとすると、一番古い日を削除するか確認します |
| 行き先ボードの表示列数 | 1〜4列 | 管理画面の設定項目としての入力可能範囲です |
| 行き先ボードの文字サイズ | 10〜40px | 同上 |

### ② 上限を設けていないもの（実質無制限）

利用者（社員）数、設備台数、お知らせ件数、敷鉄板の貸出・返却の記録件数、事前設定のプリセット件数などは、アプリ側では上限を設けていません。増やせる分だけ増やせますが、実質的な上限は下記③の外部サービスの無料枠に依存します。

### ③ 外部サービスの無料枠（アプリ自体の制限ではなくサービス側の制限）

| サービス | 用途 | 無料枠の制限 |
|---|---|---|
| Firebase Firestore（Sparkプラン＝無料の場合） | 全データの保存先（社員・設備・お知らせ・安否確認・行き先・敷鉄板など全部） | 1日あたり：読み取り5万回、書き込み2万回、削除2万回。保存容量は合計1GBまで。同時接続数にも制限があります。超えた分の操作（閲覧・保存）はその日のうちは一時的にエラーになり、翌日リセットされます |
| Firebase Authentication | ログイン | 無料枠は非常に大きく、社内利用の規模では実質的に制限を意識する必要はありません |
| EmailJS（安否確認・お知らせのメール通知） | メール送信 | 月200通まで無料。テンプレートも無料プランでは最大2個まで（安否確認用・お知らせ用ですでに2個使用しています） |
| Googleドライブ（お知らせの添付ファイル、Apps Script経由） | ファイル保存 | `osakagumi.sys@gmail.com`のGoogleドライブ容量に依存します（個人の無料Googleアカウントなら通常15GB、Gmail等と共有）。クレジットカード登録は不要です |
| Google Apps Script | 添付ファイルのアップロード・削除処理 | 1回の実行につき6分程度の実行時間上限がありますが、お知らせ添付程度のファイルサイズであれば問題になりません。1日あたりの実行回数にも無料枠の上限がありますが、社内利用の規模では十分な余裕があります |

### 補足

- 添付ファイル1個あたりのファイルサイズ上限は、アプリ側では設定していません（Googleドライブ自体の容量に準じます）。
- 名前や備考などの文字数（`maxlength`）も、アプリ側では制限していません。ただしFirestoreの1ドキュメントあたり1MBという制約はあります（通常のテキスト入力では到達しない量です）。
- 実運用でFirestoreの無料枠（1日の読み書き回数）に近づいてきた場合は、Blazeプラン（従量課金）への切り替えが必要になります。現状の使い方（社員数十名規模）であれば無料枠内で収まる可能性が高いですが、心配であれば実際の読み書き回数をFirebaseコンソールの「使用量」タブで確認することをおすすめします。

## メール通知（EmailJS）の設定

### テスト時の誤送信防止（メール送信先の上書き）

安否確認・お知らせのメール一斉送信をテストする際、うっかり全社員に送ってしまわないよう、`firebase-config.js` の `MAIL_SEND_TARGET` で送信先を一時的に絞り込めます。

```javascript
// テスト中はご自身のアドレスだけに絞る
export const MAIL_SEND_TARGET = "h.ishikawa@osakagumi.co.jp";

// 複数人でテストする場合はセミコロン区切り
export const MAIL_SEND_TARGET = "h.ishikawa@osakagumi.co.jp;n.kasai@osakagumi.co.jp";

// 本番で全社員に送る場合は必ずこれに戻す
export const MAIL_SEND_TARGET = "*";
```

`"*"` 以外を設定している間は、「社員全員にメールでも通知する」にチェックが入っていても、実際にはここで指定したアドレスにしか送信されません（発信・投稿時の確認ダイアログにも「上書き設定が有効」であることが表示されます）。**動作確認が終わったら、必ず `"*"` に戻すのを忘れないようにしてください。**

1. https://www.emailjs.com/ で無料アカウントを作成
2. 「Email Services」→「Add New Service」→ Gmailなど送信元にしたいメールアカウントを連携 → **Service ID** をメモ
3. 「Email Templates」→「Create New Template」
   - デフォルトの見た目編集（Visual）ではボタンを自由に作れないため、テンプレート編集画面右上で **「Code editor」（HTMLで直接編集するモード）** に切り替えてください
   - Subject: `{{title}}`
   - Content（HTML）の例：
     ```html
     <p>{{message}}</p>
     <p>以下のボタンから、そのまま回答できます（未ログインの場合のみログイン画面が挟まります）。</p>
     <p>
       <a href="{{link_safe}}" style="background:#2E9E8F;color:#fff;padding:10px 16px;text-decoration:none;border-radius:6px;margin-right:8px;">無事です</a>
       <a href="{{link_damage}}" style="background:#C0392B;color:#fff;padding:10px 16px;text-decoration:none;border-radius:6px;margin-right:8px;">被害があります</a>
       <a href="{{link_unknown}}" style="background:#E8853F;color:#fff;padding:10px 16px;text-decoration:none;border-radius:6px;">わからない・確認中</a>
     </p>
     <p><a href="{{link}}">システムを開く（回答内容を確認してから送信）</a></p>
     ```
   - **To Email** 欄に必ず `{{to_email}}` と入力（これを忘れると全員同じ宛先に届いてしまいます）
   - 保存後の **Template ID** をメモ（この値は`safetyTemplateId`に使います）
4. 「Account」→「General」から **Public Key** をメモ
5. `firebase-config.js` の `EMAILJS_CONFIG` を、メモした値で書き換える

```javascript
export const EMAILJS_CONFIG = {
  publicKey: "実際のPublic Key",
  serviceId: "実際のService ID",
  safetyTemplateId: "実際のTemplate ID（安否確認用）",
  noticeTemplateId: "実際のTemplate ID（お知らせ用・下記手順で作成）"
};
```

設定後、admin.htmlの「安否確認管理」タブで「社員全員にメールでも通知する」にチェックが入った状態で発信すると、社員名簿（employeesコレクション）に登録されている全員へ自動的にメールが送られます。送信はブラウザから1件ずつ行われるため、人数が多いと発信ボタンを押してから数秒〜数十秒かかります。

**ボタンを押した後の動き**：メール内のボタンを押すと、該当の状態が自動選択された状態でindex.htmlの「安否確認」タブが開きます。ログイン済みの端末ならそのまま内容を確認して「回答する」を押すだけ、未ログインの場合はメールアドレスが自動入力された状態でログイン画面が表示され、パスワード入力後に自動で同じ画面に遷移します。

### お知らせ投稿時のメール通知（2つ目のテンプレート）

EmailJSの無料プランはテンプレートを2つまで作成できるので、お知らせ用にもう1つ作成します。

1. 「Email Templates」→「Create New Template」（安否確認用とは別に、もう1つ作成）
   - Code editorに切り替え
   - Subject: `{{title}}`
   - Content（HTML）の例：
     ```html
     <p>{{author_name}} さんより、新しいお知らせが投稿されました。</p>
     <p style="white-space:pre-wrap;">{{message}}</p>
     <p><a href="{{link}}">システムでお知らせを見る</a></p>
     ```
   - **To Email** 欄に必ず `{{to_email}}` と入力
   - 保存後の **Template ID** をメモ
2. `firebase-config.js` の `EMAILJS_CONFIG.noticeTemplateId` を、メモした値に書き換える

設定後、index.htmlの「お知らせ」タブで投稿する際、「社員全員に同じ内容をメールでも送信する」にチェックが入っていれば、投稿権限を持つ人（管理者含む）が投稿するたびに、社員名簿の全員へ自動的にメールが送られます。
